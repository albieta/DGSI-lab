# Qwen3 OpenAI-Compatible Server

A FastAPI server that wraps **Qwen3 1.7B** locally and exposes an
OpenAI-compatible REST API.  Any tool that speaks the OpenAI protocol
(the `openai` Python library, `curl`, `context_explorer.py`, …) can talk
to it without modification.

---

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET`  | `/v1/models` | List available models |
| `POST` | `/v1/chat/completions` | Chat completions (streaming & non-streaming) |
| `GET`  | `/docs` | Swagger UI (auto-generated by FastAPI) |

---

## Setup

```bash
# 1. Install dependencies with uv (from the qwen3-server/ directory)
cd S2/qwen3-server
uv sync

# 2. Start the server
uv run uvicorn server:app --host 0.0.0.0 --port 8000
```

The first run downloads Qwen3-1.7B (~3 GB). Subsequent starts are fast.

---

## Testing with curl

**List models**
```bash
curl http://localhost:8000/v1/models
```

**Non-streaming completion**
```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3-1.7b",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "What is FastAPI?"}
    ],
    "temperature": 0.7
  }'
```

**Streaming completion**
```bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -N \
  -d '{
    "model": "qwen3-1.7b",
    "messages": [{"role": "user", "content": "Explain Python in one paragraph."}],
    "stream": true
  }'
```

## Testing with context_explorer.py

1. Copy `.env.example` to `../` (or the S2 directory where `context_explorer.py` lives) as `.env`:

```bash
cp .env.example ../.env
```

2. Run the explorer from the S2 folder while your server is running:

```bash
cd ..
uv run python context_explorer.py
```

The API key can be anything — the server ignores it.

## Architecture

```
server.py
├── lifespan()                 — loads model once at startup
├── GET  /v1/models            — returns model list
└── POST /v1/chat/completions
      ├── build_prompt()       — applies Qwen3 chat template
      ├── non-streaming path   — model.generate() → JSON response
      └── streaming path       — TextIteratorStreamer + background
                                 thread → Server-Sent Events
```

Key design decisions:

* **Single model load** — `lifespan` keeps the model in memory; no per-request loading overhead.
* **TextIteratorStreamer** — runs `model.generate()` in a daemon thread and yields tokens as they are produced, enabling true token-by-token SSE streaming.
* **Pydantic validation** — `ChatCompletionRequest` mirrors the OpenAI schema so malformed requests fail fast with a clear error.
* **Token counting** — prompt tokens are counted from the tokenizer input; completion tokens are counted from the sliced output.
